DoIt 项目 Lua 会员逻辑调查报告

  ---
  一、系统概述

  该项目并非传统的 VIP/订阅制会员系统，而是一个基于金币的下载服务 + 邀请返利系统。核心功能包括：用户注册登录、金币经济、邀请码、短链跳转访问控制。

  三、用户数据模型

  用户数据存储在 Redis Hash g_user_{email} 中：
  ┌───────────┬────────────────────────────┐
  │   字段    │            说明            │
  ├───────────┼────────────────────────────┤
  │ id        │ 自增用户 ID                │
  ├───────────┼────────────────────────────┤
  │ name      │ 显示名称                   │
  ├───────────┼────────────────────────────┤
  │ email     │ 邮箱（唯一标识）           │
  ├───────────┼────────────────────────────┤
  │ pwd       │ 密码（明文存储）           │
  ├───────────┼────────────────────────────┤
  │ coins     │ 金币余额（注册初始 10 枚） │
  ├───────────┼────────────────────────────┤
  │ urlclicks │ 已使用下载次数             │
  ├───────────┼────────────────────────────┤
  │ devices   │ 设备/IP 变更计数           │
  ├───────────┼────────────────────────────┤
  │ invites   │ 成功邀请人数               │
  ├───────────┼────────────────────────────┤
  │ inviteby  │ 邀请人 userID              │
  ├───────────┼────────────────────────────┤
  │ ip / ipv6 │ 最后登录 IP                │
  └───────────┴────────────────────────────┘
  ---
  四、金币经济体系

  注册 → 获得 10 金币
  邀请 1 人 → 获得 +100 金币
  每次下载 → 消耗 1 金币
  金币耗尽 → 阻止下载，提示"金币已用完-请充值或邀请返利"

  余额计算：剩余 = coins - urlclicks

  ---
  五、邀请系统

  - 邀请码 = 用户 ID（自增数字）
  - 邀请链接格式：https://域名/?{userID}
  - 注册时前端从 URL 参数捕获 inviteby，存入 localStorage，随注册请求提交
  - 被邀请人注册成功后，邀请人获得 +100 金币 + 邀请计数 +1

  相关 Redis 键：
  - g_invite_codes_index（Hash）：userID → email 映射
  - g_users_index（Set）：所有已注册邮箱集合

  七、访问控制与限流

  在 url.lua 中实现了多层访问控制：
  ┌─────────────┬────────────┬────────────────────────────┬─────────┐
  │   限制项    │    阈值    │          Redis 键          │   TTL   │
  ├─────────────┼────────────┼────────────────────────────┼─────────┤
  │ 每日下载    │ 10 次/天   │ g_click_rate_daily_{token} │ 25 小时 │
  ├─────────────┼────────────┼────────────────────────────┼─────────┤
  │ 7日下载     │ 128 次/7天 │ g_click_rate_{token}       │ 7 天    │
  ├─────────────┼────────────┼────────────────────────────┼─────────┤
  │ IP 注册限制 │ 1 次/IP    │ g_reg_ip_{ip}              │ 7 天    │
  ├─────────────┼────────────┼────────────────────────────┼─────────┤
  │ 设备变更    │ 128 次     │ devices 字段（永久）       │ —       │
  └─────────────┴────────────┴────────────────────────────┴─────────┘
  超过设备限制会直接封号："账号已失效-请重新购买账号"

  ---
  八、管理后台 (admin.lua)

  - 硬编码管理 Token：admintesttoken
  - 基于时间窗口验证（±10 秒）
  - 支持批量插入短链映射（上限 100 条）
  - 数据存储在 g_urls（Hash：短链 ID → 真实 URL）

  ├────────┼─────────────────────────────────────────┤

  ├────────┼─────────────────────────────────────────┤

  ---
  十一、结论

  该系统的"会员"模型是单层扁平结构，没有 VIP 等级或订阅套餐。核心商业模式是：注册赠送少量金币 → 金币耗尽后通过邀请返利（或隐含的充值/购买账号）获取更多下载次数。访问控制通过金币余额、下载频率、设备绑定三重机制实现。
